## What will appear here

### Metric tables

| File | Produced by | Contents |
|---|---|---|
| `metrics_all_models.csv` | NB03 §2.1 / §2.3 | Consolidated leaderboard: accuracy, balanced accuracy, macro-F1, weighted-F1, MCC, macro AUC, per-class P/R/F1/support |
| `metrics_baseline.csv` | NB03 §2.2 | TF-IDF + Logistic Regression alone |
| `group_comparison.csv` | NB03 §3.1 | Bangla-specific vs. multilingual vs. classical, grouped |

### Figures

| File | Produced by | Contents |
|---|---|---|
| `confusion_<model>.png` | NB03 §5.1 | Counts and row-normalised confusion matrices, side by side |
| `roc_<model>.png` | NB03 §5.1 | One-vs-rest ROC with per-class AUC |
| `bar_macro_f1.png` | NB03 §5.1 | Macro-F1 by model |
| `bar_accuracy.png` | NB03 §5.1 | Accuracy by model |
| `label_distribution.png` | NB03 §5.2 | Label proportions per split, to verify stratification held |

`<model>` is the registry key with `/` replaced by `__`, e.g. `confusion_csebuetnlp__banglabert.png`.

### Slice tables

| File | Produced by | Question it answers |
|---|---|---|
| `slice_by_source_<model>.csv` | NB03 §4.1 | Does the model generalise across platforms, or learn platform style? |
| `slice_by_negation_<model>.csv` | NB03 §4.2 | Did negation-scope tagging actually help? |
| `slice_by_length_<model>.csv` | NB03 §4.3 | How does accuracy vary with comment length? |

### Error samples

| File | Produced by | Contents |
|---|---|---|
| `errors_<model>.csv` | NB03 §6.1 | 20 sampled misclassifications with true label, predicted label, source and negation flag — read by hand for the qualitative analysis in `docs/04_analysis.md` §4.8.2 |

## Reading order

Once populated, these are the files that carry the report's argument, in the order `docs/04_analysis.md` consumes them:

1. `metrics_all_models.csv` — the leaderboard (§4.5)
2. `group_comparison.csv` — the central question (§4.6)
3. `slice_by_source_<model>.csv` — generalisation (§4.7.1)
4. `slice_by_negation_<model>.csv` — negation benefit (§4.7.2)
5. `slice_by_length_<model>.csv` — length effect (§4.7.3)
6. `confusion_<model>.png` + `errors_<model>.csv` — qualitative error themes (§4.8)

The reproducibility hashes live elsewhere: `dataset/preprocessed/data_manifest.csv` (§4.9).

## Reproducing

```bash
# after Notebook 01 and Notebook 02 have run
python src/evaluate.py --all                 # every trained checkpoint + baseline
python src/evaluate.py --model banglabert    # one model
python src/evaluate.py --baseline-only       # TF-IDF alone, CPU, no checkpoint
```

`--baseline-only` is the cheapest sanity check in the whole project: it needs no GPU, no checkpoint and no Kaggle credentials beyond what Notebook 01 already fetched, and it produces the reference number that every transformer result must be read against.
